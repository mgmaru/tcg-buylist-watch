# tcg-buylist-watch

カードショップのポケカ買取表を1日1回取得して、価格の変化と店ごとの差を記録します。

フリマで仕入れて店に売るときの「いま、どの店がいくらで買い取るか」を、手で調べずに追えるようにするためのものです。

## 対応している店

| 店 | 取得元 | 件数の目安 | 取れる価格 |
|---|---|---|---|
| カードラッシュ (`cardrush`) | 買取表の公開ページ（100件ずつ、約140ページ） | 約14,000件 | 買取 |
| 晴れる屋2 (`hareruya2`) | 買取リストのページが読み込むJSON（1回） | 約23,500件 | 買取・販売 |
| 遊々亭 (`yuyutei`) | 買取と販売の検索結果ページ（600件ずつ、合わせて約65ページ） | 約23,400件 | 買取・販売 |

## 使い方

Python 3.10以上で動きます。外部ライブラリは使いません。

```sh
export PYTHONPATH=src

# 全店を同時に取得して data/ に保存（いちばん遅い店に合わせて5〜6分。--jobs 1 で順番に取得）
python -m buylist_watch fetch

# 1店だけ、最初の3ページだけ試す
python -m buylist_watch fetch --source cardrush --max-pages 3

# ある店の買取価格が、別の店の販売価格より高いカードを探す
python -m buylist_watch compare --min-buy 3000 --top 20

# チェッカーのサイトを _site/ に作る
python -m buylist_watch site

# テスト
python -m unittest discover -s tests
```

## チェッカーが読むデータ

`site` は `web/` を出力先にコピーして、次の2つのファイルを作ります。

- `data.json`：今の買取表、直近7日の値動き、店の差。ページを開いたときに読みます
- `history.json`：カードごとの買取価格の履歴（グラフ用）。日がたつほど増えるので分けてあり、一覧を出したあとで読みます

`web/index.html` の中で「どこから読むか・どこに保存するか」を知っているのは、`Source`（買取表と履歴を読む）と `UserStore`（ウォッチや設定を端末に保存する）の2つだけです。取得元をサーバーのAPIなどに変えるときは、この2つを差し替えます。

フリマへのリンクは、`MARKETS`（`web/index.html`）にまとめてあります。メルカリ・Yahoo!フリマ・ヤフオクそれぞれが、検索語・値段の上限・カードの状態をURLにどう書くかを持っています。画面では状態を共通の段階（指定なし／目立った傷なし以上／未使用に近い以上／新品・未使用のみ）で選び、各フリマの値に読み替えます。フリマを増やすときは、ここに1つ足します。

## 件数が急に減ったとき

店が買取表を入れ替えている途中に取りに行くと、一部のカードしか載っていない状態を拾うことがあります（カードラッシュで、約14,000件が15分ほど約6,500件になった例があります）。そのまま保存すると大量の「掲載終了」を誤って記録するので、`fetch` は次のように動きます。

1. 件数が前回の7割を下回ったら保存せず、10分待ってその店だけ取り直す（2回まで。`--shrink-wait`、`--shrink-retries` で変更）
2. それでも減ったままなら、前回のデータを残して終了コード1で終わる。見送ったことは `data/<店>/meta.json` の `held` に残り、チェッカーの取得日時の下に表示される
3. 減った状態が24時間続いたら、店が本当に掲載を減らしたとみなして保存する
4. すぐ保存したいときは `--force`

## 保存されるデータ

```
data/<店>/latest.csv          最新の全件（毎回上書き）
data/<店>/changes/<日付>.csv   前回から変わった行だけ
data/<店>/meta.json           取得日時と件数
reports/cross_shop.csv        店をまたいだ比較の結果
```

`changes` の `change` 列は次のどれかです。

- `new`：新しく掲載された
- `removed`：掲載がなくなった
- `up` / `down`：買取価格が上がった / 下がった
- `sell`：販売価格だけが変わった

全件を毎日残すとリポジトリがすぐ大きくなるので、履歴は差分だけにしています。

## チェッカー（GitHub Pages）

`web/index.html` が画面で、`site` コマンドが `data/` から `data.json` を作ります。3つの表示があります。

- **チェック**：カード名や型番で探して、買取価格と仕入れの上限をひと目で見る。カードを押すと、店ごとの買取価格、出品価格を入れたときの利益、買取価格の推移が開く。各カードから、メルカリの新着・売り切れ、ヤフオクの落札相場を開ける。☆でウォッチに入れたカードは、開いた直後に並ぶ
- **値動き**：直近7日で買取価格が上がった・下がった・掲載が終わった・新しく載ったカード（買取3,000円以上）
- **店の差**：ある店の買取価格が、別の店の販売価格より高い組み合わせ

仕入れの上限と利益は、状態Aを100%として A-は56%、Bは20% で買い取られる想定です。仮の比率なので、実際の査定とは違うことがあります。出品価格の入力はブラウザにだけ保存されます。

載せるのは買取1,000円以上のカードだけです。

メルカリとヤフオクは、検索結果のページを開くリンクだけです。どちらも自動取得を認めていないので、このツールからは取得しません。

`?q=ゲンガー 042/090` のように URL に付けると、検索した状態で開きます。

## 取得と公開

定期実行は今は止めています。カードラッシュが GitHub のサーバーからの接続を拒否する（403）ためです。

- `.github/workflows/fetch.yml`：Actions の画面から手動で実行すると、取得・コミット・公開をします。GitHub 上ではカードラッシュの取得は失敗します
- `.github/workflows/deploy.yml`：`main` にデータやコードがプッシュされると、保存済みのデータからチェッカーを作り直して公開します

カードラッシュの価格を更新するには、接続できる環境（自宅の回線など）で `fetch` を実行して、`data/` をプッシュします。

Pages を使うには、リポジトリの Settings → Pages で Source を「GitHub Actions」にしてください。非公開リポジトリで Pages を使うには、GitHub の有料プランが必要です。公開したページは、URLを知っていれば誰でも見られます。

## 比較結果を読むときの注意

- 店をまたいだ突き合わせは「名前・型番・値段を左右する仕様」で行います。仕様は、1ED／アンリミ（再販）、ミラーの種類（マスターボール・モンスターボールなど）、未開封、エラー、色違いなどを共通の呼び名にそろえて比べます（`compare.py` の `_HARD_RULES`）。保存するデータは店の書き方のままです。
- 店ごとの書き方の違いで、同じカードが別々に出ることがあります。結果は候補として見て、買う前に両方の店のページで仕様を確かめてください。
- 晴れる屋2の販売価格は、在庫がなくても表示されます。その値段で買えるとは限りません。
- 遊々亭の販売価格は、在庫があるものだけ記録しています。
- 遊々亭の扱いはBWシリーズ以降です。DPやPCGなど古いシリーズは載っていません。
- 買取価格は美品が前提です。傷があると大きく下がります。

## 取得の作法

- 取得は1日1回、1件ごとに1.5秒空けます。
- カードラッシュは、robots.txt が禁止している `/api` を使わず、公開ページだけを読みます。
- User-Agent にこのリポジトリのURLを入れています。
- 個人の調査用です。取得したデータの再配布は想定していません。各店の利用規約を確認のうえ使ってください。

## 店を追加するには

`src/buylist_watch/sources/` に、`NAME` と `fetch(fetcher, max_pages)` を持つモジュールを作り、`sources/__init__.py` の `SOURCES` に登録します。`fetch` は `Price` を1件ずつ返します。
